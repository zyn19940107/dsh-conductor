# quixbugs on 臂：每条记录对应的提示词版本

这些是 2.10.4 前后调提示词时的实验记录。**同一个任务在不同提示词版本下跑出来的**，
所以数字要按版本读，不能混着算。

| 记录 | 提示词版本 | 内容 |
|---|---|---|
| `quixbugs-on-1..5.json` | 2.10.3 | 无"验收归属"规则。父代理把全局验收写进每个 worker 的 task，worker 都跑根目录 `check.py` |
| `quixbugs-on-6..8.json` | 2.10.3 + 验收规则 v1 | "二选一"：节点自证，或父代理验；节点不再跑全局 check，改为临时脚本验自己那份 |
| `quixbugs-on-9..11.json` | 2.10.3 + 验收规则 v2 | v1 加硬：父代理验时节点 task 不许有任何"跑"的动作 |
| `quixbugs-on-12..14.json` | 2.10.3 + 验收规则 v3 | 改成按验收信号判定：全局验收归父代理，节点 task 不写证明步骤 |
| `quixbugs-on-15..19.json` | **2.10.4** | v3 + "先读后派"（`ROUND_LOOP`）：多个节点需要同一批起点信息时，先单独一轮读完再派 |

## 读这些数字时的两个坑

1. **n 小、方差大**：同形状的归一化时间能差 2–3 倍（on-15 249s vs on-17 92s），
   中位数只能作方向参考。
2. **形状是模型自己选的**：v1–v3 期间没有规则强制形状，同一版本下既有"先读后派"也有
   "首轮直接派"。按形状分组得到的对比是**观察数据**，不是受控 A/B。
